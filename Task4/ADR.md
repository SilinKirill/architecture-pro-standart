# ADR-002. Передача ставок в кол-центры

### **Название задачи:** ADR-002. Передача актуальных депозитных ставок в кол-центры

### **Автор:** Кирилл Силин

### **Дата:** 02.07.2026

### **Функциональные требования**

| **№** | **Действующие лица или системы**                                                               | **Use Case**                            | **Описание**                                                                                                                                                                                                                                                                         |
|:-----:|:-----------------------------------------------------------------------------------------------|:----------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|  UC1  | Клиент, менеджер кол-центра банка, система кол-центра, сервис депозитных заявок, АБС           | Консультация клиента в кол-центре банка | 1. Клиент звонит в кол-центр банка.<br>2. Менеджер открывает карточку консультации.<br>3. Система кол-центра получает актуальные ставки по депозитам через API сервиса депозитных заявок.<br>4. Менеджер консультирует клиента по текущим условиям.                                  |
|  UC2  | Сервис депозитных заявок, АБС, SFTP-канал, система партнёрского кол-центра                     | Передача ставок партнёрскому кол-центру | 1. Сервис депозитных заявок получает актуальные ставки из АБС.<br>2. Сервис формирует файл ставок с версией и датой актуальности.<br>3. Файл передаётся партнёру через SFTP-канал.<br>4. Система партнёрского кол-центра загружает файл для консультаций.                            |

Бэк-офис обновляет ставки и особые условия в АБС.<br>2. Сервис депозитных заявок синхронизирует новую версию ставок.<br>3. Система кол-центра банка получает обновления через API ставок сервиса депозитных заявок.<br>4. Партнёрский кол-центр получает новую файловую выгрузку. |

### **Нефункциональные требования**

| **№** | **Требование**                                                                 |
|:-----:|:-------------------------------------------------------------------------------|
|   U   | Удобство использования (Usability)                                             |
|  U1   | Менеджер кол-центра видит ставки в рабочем интерфейсе своей системы.           |
|   R   | Надёжность (Reliability)                                                       |
|  R1   | Ошибка передачи ставок не должна блокировать приём депозитных заявок.          |
|  R2   | Файловая выгрузка партнёру должна поддерживать повторную отправку.             |
|   P   | Производительность (Performance)                                               |
|  P1   | Получение ставок в системе кол-центра банка выполняется без заметной задержки. |
|   S   | Поддерживаемость (Supportability)                                              |
|  S1   | Формат API и файла ставок документируется и версионируется.                    |
|  S2   | Передача ставок логируется и мониторится.                                      |
|  +R   | + Ограничения (Restrictions)                                                   |
|  +R1  | АБС остаётся источником актуальных ставок.                                     |
|  +R2  | Кол-центры не получают прямой доступ к БД АБС.                                 |
|  +R3  | Партнёрский кол-центр получает ставки файлом через SFTP-канал.                 |
|  +R4  | В файлах партнёру не передаются клиентские персональные данные.                |

### **Решение**

Для передачи ставок используем существующий **сервис депозитных заявок MVP**. Он получает ставки из АБС, хранит актуальную версию и отдаёт её в каналы консультаций.

Система кол-центра банка получает ставки через внутренний API сервиса депозитных заявок. Это позволяет менеджерам консультировать клиентов без прямого доступа к АБС.

Для партнёрского кол-центра сервис депозитных заявок формирует файл ставок и передаёт его через SFTP-канал. Файл содержит версию, дату актуальности и набор ставок по депозитным продуктам.

АБС остаётся источником ставок. Кол-центры не обращаются напрямую к БД АБС.

Основные интеграции:

| Интеграция                                                      | Назначение                                     |
|:----------------------------------------------------------------|:-----------------------------------------------|
| АБС ↔ сервис депозитных заявок                                  | Синхронизация актуальных ставок и версий.      |
| Система кол-центра банка → API ставок сервиса депозитных заявок | Получение ставок для консультации клиента.     |
| Сервис депозитных заявок → SFTP-канал партнёра                  | Передача файла ставок партнёрскому кол-центру. |
| SFTP-канал → система партнёрского кол-центра                    | Загрузка файла ставок в систему партнёра.      |

### **Альтернативы**

| Альтернатива                                 | Причина отказа                                      |
|:---------------------------------------------|:----------------------------------------------------|
| Дать кол-центрам прямой доступ к АБС         | Усилит нагрузку на АБС и нарушит изоляцию систем.   |
| Передавать ставки партнёру вручную по e-mail | Высокий риск устаревших данных и ручных ошибок.     |
| Реализовать API для партнёрского кол-центра  | Партнёр не готов выполнять API-вызовы.              |
| Хранить ставки отдельно в системе кол-центра | Появится второй источник ставок и риск расхождений. |

**Недостатки, ограничения, риски**

1. Партнёрский кол-центр может консультировать по устаревшему файлу, если выгрузка не прошла.
2. Нужно контролировать версию и дату актуальности файла ставок.
3. Сбой SFTP-канала требует повторной отправки и мониторинга.
4. Изменения в формате ставок потребуют согласования с партнёром.
5. При недоступности АБС сервис должен отдавать последнюю актуальную версию ставок.
6. Если ставки обновляются часто, нужно согласовать допустимую задержку передачи в кол-центры.

### **Крупные задачи по системам**

| Система                      | Крупные задачи                                                                                                  |
|:-----------------------------|:----------------------------------------------------------------------------------------------------------------|
| АБС                          | Реализовать справочник ставок и особых условий. Подготовить интеграцию отдачи ставок сервису депозитных заявок. |
| Сервис депозитных заявок MVP | Реализовать синхронизацию ставок из АБС, API ставок для кол-центра банка и файловую выгрузку партнёру.          |
| Система кол-центра банка     | Добавить экран просмотра депозитных ставок в рабочий интерфейс менеджера.                                       |
| Партнёрский кол-центр        | Настроить приём файла ставок через SFTP и загрузку ставок в свою систему.                                       |
| Сайт и интернет-банк         | Использовать тот же источник актуальных ставок для отображения условий депозитов.                               |
| Общие работы                 | Согласовать формат файла ставок, версионирование, мониторинг, E2E-тестирование и пилотный запуск.               |
