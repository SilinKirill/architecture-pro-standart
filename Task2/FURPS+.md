| Код | Требования                                                               | Комментарий                                                 |
|-----|--------------------------------------------------------------------------|-------------------------------------------------------------|
| F   | Функциональные (Functionality)                                           |                                                             |
| F1  | Клиент подаёт заявку на депозит с сайта или из интернет-банка.           | В MVP заявку обрабатывает сотрудник.                        |
| F2  | Клиент подаёт заявку на кредит с сайта или из интернет-банка.            | Для сайта возможно предварительное решение.                 |
| F3  | Ставки и условия продуктов хранятся централизованно и доступны системам. | Нужно уйти от XLS.                                          |
| F4  | Система поддерживает персональные ставки и предодобренные предложения.   | Для клиентов интернет-банка.                                |
| F5  | Клиент получает СМС-коды и СМС-уведомления по заявкам.                   | Подтверждение операций и статусы.                           |
| U   | Удобство использования (Usability)                                       |                                                             |
| U1  | Интерфейсы соответствуют дизайн-системе банка.                           | Единый UX для сайта и интернет-банка.                       |
| U2  | Клиент видит условия продукта до отправки заявки.                        | Ставка, сумма, статус, условия.                             | 
| R   | Надёжность (Reliability)                                                 |                                                             |
| R1  | Сервисы цифровых заявок доступны 24/7 с SLA 99,9%.                       | Нужны резервный ЦОД и восстановление.                       |
| R2  | Заявки не теряются и не дублируются при сбоях интеграций.                | Нужны retry и идемпотентность.                              |
| P   | Производительность (Performance)                                         |                                                             |
| P1  | Клиентские операции выполняются без заметной задержки.                   | Справочники — быстрее 1 секунды.                            |
| P2  | Предодобренные кредитные заявки обрабатываются в тот же рабочий день.    | Текущий обмен раз в сутки мешает цели.                      |
| S   | Поддерживаемость (Supportability)                                        |                                                             |
| S1  | Новые интеграции документируются и имеют понятные контракты.             | Нужно для развития после MVP.                               |
| S2  | Заявка трассируется между системами по единому идентификатору.           | Для поддержки и разбора ошибок.                             |
| +R  | + Ограничения (Restrictions)                                             |                                                             |
| +R1 | Чувствительные данные передаются только по защищённому каналу.           | Нужно шифрование трафика.                                   |
| +R2 | Новые клиенты проходят идентификацию в отделении.                        | Ограничение процесса банка.                                 |
| +R3 | Избегаем прямой интеграции интернет-банка с АБС.                         | АБС перегружена.                                            |
| +R4 | Скоринг нельзя нагружать массовыми предрасчётами.                        | Система критична и уже нагружена.                           |
| +R5 | Используем существующие технологии банка.                                | MS SQL, Oracle, Java, .NET; Kafka — с учётом совместимости. |
| +R6 | Минимизируем доработки ядра интернет-банка подрядчиком.                  | Лучше вынести бизнес-функции из ядра.                       |
